# 0) 문서 목적
관객 대상(B2C) 화면·기능의 요구사항을 정의한다.
정책은 `PRD_MAIN.md`를 상속하며, 본 문서는 화면/상태/오류/카피/QA 기준을 구체화한다.

# 1) IA & 접근 가드
- **공개 라우트**: `/`, `/events`, `/events/{slug}`
- **보호 라우트(로그인 필요)**: `/events/tickets/{slug}` (응모 폼)
- **가드 규칙**
  - 미로그인 사용자가 응모 폼 접근 시 로그인 페이지로 리다이렉트
  - 승인되지 않은 이벤트는 공개 목록에 미노출

# 2) 핵심 사용자 플로우
1) **홈** 방문 → 추천 공연 및 진행 중인 티켓 이벤트 확인
2) **이벤트 목록** (`/events`) → 필터/검색으로 관심 이벤트 탐색
3) **이벤트 상세** (`/events/{slug}`) → 공연 정보 및 이벤트 세부사항 확인
4) **응모** (`/events/tickets/{slug}`) → 로그인 후 연락처 정보 입력하여 응모
5) **결과 확인** → 이메일/SMS로 당첨 여부 확인

# 3) 페이지별 기능 정의

## 3.1 홈 `/`

### 3.1.1 데이터 의존성
- GET /api/events?status=approved&sort=latest&limit=6 → 최신 이벤트
- GET /api/performances?featured=true&limit=4 → 추천 공연

### 3.1.2 UI 블록
- **히어로 섹션**: 플랫폼 소개 및 주요 가치 제안
- **진행 중인 이벤트**: 현재 응모 가능한 티켓 이벤트 6개 (카드 형태)
- **추천 공연**: 주목할 만한 공연 4개
- **CTA**: "모든 이벤트 보기" → `/events`

### 3.1.3 이벤트 카드 컴포넌트
- 공연 포스터
- 이벤트 제목
- 보상 (예: "2인 초대권")
- 응모 마감일
- 상태 배지 (진행중/마감임박)
- 클릭 → 이벤트 상세 페이지

### 3.1.4 접근성/성능
- 이미지 지연 로딩
- LCP ≤ 2.5s 목표
- 키보드 탐색 지원

## 3.2 이벤트 목록 `/events`

### 3.2.1 데이터 의존성
- GET /events?status=approved&genre[]&region[]&q&sort&page&size
- SSR 1페이지 + CSR 무한 스크롤(12개씩)

### 3.2.2 필터/정렬/검색
**필터:**
- 장르 (다중 선택): 연극, 뮤지컬, 음악, 무용, 전시 등
- 지역: 서울, 경기, 지방
- 상태: 진행중, 마감임박

**정렬:**
- 최신순
- 마감임박순
- 인기순 (응모자 수 기준, 향후)

**검색:**
- 공연 제목 부분 일치
- 300ms 디바운스

### 3.2.3 리스트/카드
- 이벤트 카드 그리드 (모바일 1열, 태블릿 2열, 데스크톱 3열)
- 무한 스크롤: 뷰포트 하단 200px 진입 시 다음 페이지 프리페치
- "필터 초기화" 버튼

### 3.2.4 예외/오류 UX
- 결과 없음: "조건에 맞는 이벤트가 없습니다" + "필터 초기화"
- 요청 실패: 상단 토스트 + 재시도, 마지막 성공 결과 캐시 유지

### 3.2.5 분석 태깅
- `event_list_view{filters, sort}`
- `event_card_click{eventId}`
- `filter_change{key, value}`

## 3.3 이벤트 상세 `/events/{slug}`

### 3.3.1 데이터 의존성
- GET /events/{slug} → 이벤트 정보 + 연결된 공연 정보
- GET /events/{slug}/stats → 현재 응모자 수 (향후)

### 3.3.2 레이아웃/섹션
**상단 메타:**
- 공연 포스터
- 이벤트 제목
- 보상 (예: "2인 초대권")
- 응모 기간
- 공연 날짜
- 상태 배지

**본문:**
- 이벤트 설명
- 공연 정보 (제목, 장르, 장소, 기간)
- 참여 방법 안내
- 유의사항

**CTA 영역:**
- "응모하기" 버튼 (상태에 따라 활성/비활성)
- 티켓 구매하기 링크 (외부 링크)

### 3.3.3 응모 CTA 상태
**활성 조건:**
- 이벤트 status = approved
- 현재 시각이 응모 기간 내
- 로그인 상태

**비활성 메시지:**
- 미로그인: "로그인 후 응모 가능합니다"
- 응모 전: "응모 시작 전입니다"
- 응모 후: "응모가 마감되었습니다"
- 승인 대기중: "관리자 승인 대기 중"
- 이미 응모: "응모가 완료되었습니다"

### 3.3.4 분석 태깅
- `event_detail_view{eventId, dwellSec}`
- `apply_cta_click{eventId, status}`

## 3.4 응모 폼 `/events/tickets/{slug}`

### 3.4.1 접근 가드
- 미로그인 → 로그인 페이지 리다이렉트
- 이벤트 상태/기간 검증 → 미충족 시 상세 페이지로 리다이렉트

### 3.4.2 폼 항목/검증
**필수 필드:**
- 이름 (2자 이상)
- 연락처 (전화번호 또는 이메일)
- 개인정보 수집 및 이용 동의 (필수)

**선택 필드:**
- 마케팅 수신 동의

**실시간 검증:**
- blur 시점에 필드별 검증
- 에러 메시지 필드 하단 노출

### 3.4.3 제출/서버 로직
**POST /api/entries**
- Body: `{campaignId, name, contact, marketingConsent}`
- 성공 (201):
  - 완료 화면 표시
  - "응모가 완료되었습니다. 추첨 결과는 이메일/SMS로 안내됩니다."
- 실패:
  - 409 (중복): "이미 응모하셨습니다"
  - 412 (사전조건): "응모 기간이 아니거나 승인되지 않은 이벤트입니다"
  - 422 (필드 오류): 폼 내 필드별 표기
  - 5xx: 재시도 버튼

### 3.4.4 보안/안티어뷰즈
- 서버 유니크키: UNIQUE(campaign_id, contact_hash)
- Rate Limit: 동일 IP 10회/분
- CSRF 방어

### 3.4.5 분석 태깅
- `entry_submit_attempt{eventId}`
- `entry_submit_success{eventId}`
- `entry_submit_error{eventId, code}`

## 3.5 당첨 확인 (향후)
- `/me/entries`: 내 응모 내역 및 당첨 여부 확인
- 이메일/SMS 링크를 통한 개별 확인 페이지

# 4) 공통 에러 코드 & 카피

**401**: "로그인이 필요합니다"
**403**: "접근 권한이 없습니다"
**409**(중복 응모): "이미 응모하셨습니다"
**412**(사전조건 미충족): "현재 응모할 수 없는 이벤트입니다"
**422**: "입력값을 확인해주세요"

# 6) QA 수락 기준

## 6.1 접근/보안
- 미로그인 사용자가 응모 폼 접근 시 로그인 리다이렉트 ⇒ PASS
- 승인되지 않은 이벤트는 공개 목록 미노출 ⇒ PASS

## 6.2 응모
- 동일 캠페인 재제출 시 **409** + 안내 메시지 ⇒ PASS
- 이벤트 기간 외 응모 시 차단 ⇒ PASS
- 필수 필드 누락 시 제출 불가 + 필드 에러 표시 ⇒ PASS

## 6.3 UI/UX
- 응모 CTA 상태(활성/비활성)가 이벤트 상태에 따라 정확히 반영 ⇒ PASS
- 필터/정렬 변경 시 URL 쿼리 동기화 ⇒ PASS
- 무한 스크롤 정상 작동 ⇒ PASS
