## 1. 전략 방향 전환 배경

초대권 이벤트 시스템 완성까지 시간이 필요하다. 그 사이 SNS 팔로워들이 웹사이트에서 즉시 가치를 경험할 수 있어야 한다. **공연 큐레이션 허브**를 먼저 완성하고, 공연 정보 검색 강화 → 공연 취향 분석 → 초대권 재활성화 순으로 단계적으로 진행한다.

```
Phase 1 (지금)     SNS 팔로워 유입 → 큐레이션 에세이 + 픽 공연 상세 정보
Phase 2 (다음)     공연 정보 검색 강화 (KOPIS 데이터 누적, /shows 고도화)
Phase 3 (이후)     공연 취향 분석 (/taste 고도화, 개인화 추천)
Phase 4 (나중)     후기/로그인/북마크 시스템 완성
Phase 5 (나중)     초대권 이벤트 시스템 재활성화
```

## 8. 일일 작업 원칙

1. **빌드 확인 필수**: 매일 작업 종료 전 `npm run build` 통과 확인
2. **graceful degradation**: 새 DB 기능은 42P01/42703 에러 핸들링 필수 (migration-not-applied 대비)
3. **URL은 유지**: 숨기는 기능은 nav에서만 제거, 라우트 파일 삭제 금지
4. **모바일 우선**: UI 변경 시 항상 모바일 뷰 먼저 확인
5. **DB 변경 주의**: 마이그레이션 파일은 로컬 우선 테스트 후 Supabase 적용
